# v1.1.0 — Roadmap

Reference for V, Claude (chat), and Claude Code (agent). Status: Not Started / In Progress / Done.

---

### 1. Deterministic edge-case seed corpus
**Status:** Done
**Touches:** `Property.java`
**What:** Before the random example loop in `check()`, run a small fixed set of deterministic replay-mode `DataSource`s (all-zero buffer, all-`0xFF` buffer) as ordinary examples. All-zero already drives every primitive to its D4 shrink target (min/false/empty); all-`0xFF` drives the opposite boundary.

---

### 2. `generationBudget()` on `@Property`
**Status:** Done
**Touches:** `junit/Property.java`, `junit/PropertyExtension.java`
**What:** Add `int generationBudget() default -1;` to the annotation. When set, call `.withGenerationBudget(...)` on the runner in `PropertyExtension`, mirroring the existing `seed()` pattern.

---

### 3. Docs cleanup
**Status:** Done
**Touches:** `Generators.java` (Javadoc only)
**What:** Document default bounds for `maps()`/`sets()` (same one-line pattern already present on `lists()`/`strings()`). Add `.jhusk/` CI guidance (gitignore vs. cache) — README or a short doc comment on `FailureStorage`.

---

### 4. Exhaustive `booleans()` + `Generators.exhaustive(T...)`
**Status:** Done
**Touches:** `Generators.java`, `internal/DataSource.java` (`drawBoolean()` if needed)
**What:** `booleans()` already gets full true/false coverage for free from the item #1 edge-case corpus (0x00 -> false, 0xFF -> true) — confirmed with a test, no `DataSource.java` change needed. Added `Generators.exhaustive(T...)` for small explicit domains (enums, small sets), reusing `oneOf()`'s D3 selector so `values[0]` is the D4 shrink target and `values[last]` is guaranteed via the same edge-case corpus.

---

### 5. `Property.assuming(Predicate<T>)`
**Status:** Done
**Touches:** `Property.java`
**What:** Property-level precondition distinct from `filter()` — checked once against the fully-assembled value right before the assertion runs, wired into both the edge-case corpus and the random loop. Rejections count as invalid runs with their own counter, reported separately from filter/overrun causes; the exhaustion diagnostic now distinguishes overrun-only, assumption-only, filter-only, and mixed-cause exhaustion.

---

### 6. Delta-debugging chunk-removal shrink pass
**Status:** Done
**Touches:** `internal/Shrinker.java`
**What:** Add hierarchical/binary span removal (try deleting halves of sibling `list-element` spans, ddmin-style) before falling back to existing one-at-a-time `spanDeletion()`. Fixes the Round 5 benchmark finding — a 27-op bloated result after exhausting the 5000-attempt cap, where jqwik found a 6-op minimum.

---

### 7. Stateful/model-based testing (`Commands` abstraction)
**Status:** Done
**Touches:** New public API surface (`.internal` + `io.github.nikhilvirdi.jhusk` package) — design/RFC needed before implementation
**What:** Each command: precondition, execution against the real system, execution against a model, postcondition comparing both. Generate sequences of commands, run against both, shrink the failing sequence itself on the same byte-stream substrate — so sequence-shrinking inherits generic, free shrinking like everything else. Built last, deliberately, so it inherits the fixed shrinker from #6.

---

## Order rationale
1-5 are small and isolated — build up confidence and passing tests with low risk. 6 fixes the shrinker directly. 7 is the largest, highest-risk item, and depends on 6's shrink quality to actually perform well on sequences — building it last means it inherits the fix instead of re-exposing the same weakness Round 5 found.
